# 完整微调后，选定粗块内部还留下多少细定位误差？

日期：2026-09-11。状态：诊断定义、实现与CPU小型测试完成；正式分析尚未运行。

## 为什么需要这项补充

[完整系统比较](2026-09-11-full-hrnet-dino-comparison.md)中，DINO/HRNet在共同1,746个有位置验证目标上的@8命中为1422/1562，@16为1537/1579。8到16像素误差区间的数量分别为115和17；两系统@8的140次命中差可算术分解成@16的42次差与区间内的98次差。这是误差分布分解，不是对分辨率、量化或motion的因果归因。

[搜索支撑分析](2026-09-11-search-support.md)又发现，精细位置差距主要发生在旧局部范围可覆盖的目标中。旧冻结小样本已做过[固定预测粗块的四子格oracle](2026-09-10-local-cost.md)，但完整数据和共同微调改变了表示与头，旧结果不能代替当前模型的读出判断。这一新证据支持补做同一种廉价诊断，不重开旧cost或宽度实验。

## 固定预测块的几何问题

当前DINO最终输出72×128，每格对应原图10像素；PixelShuffle×2的每个原生36×64粗块产生四个子格。对每一条实际预测，固定它选中的粗块，仅用GT在该块的四个合法输出中心中选择最近点。保持模型、检查点、实际预测、存在分数及阈值不变，oracle另作诊断统计。

全图最近输出格中心每轴至多距标签5像素，二维误差至多约7.07，因此@8在几何上可以全部命中。当前诊断测实际粗块与子格选择，不把10像素格距直接当成PCK@8不可突破的量化上限。

该oracle一定包含原预测点，因此其误差不能大于原误差。对每个有位置目标，@8分成互斥三类：实际已命中；实际未命中但选定块内存在8像素内子格；四个子格都不在8像素内。另报预测原生块与GT原生块相同的数量。

这三个指标不能混用：GT在相邻块也可能距当前块边缘子格不到8像素；同块则仍可能选错子格。因此不能用“是否等于GT粗块”直接代替PCK或oracle成功。

VC0没有合法位置，保持其实际坐标和存在分数，不为其构造oracle中心。VC1/2/3按现有位置协议分别报告；VC3的几何结果仍不意味着该帧有可见球外观。

## 范围与验证

只读已完成的DINO历史组config、results和train/val预测；不读图像、checkpoint或最终测试，不执行模型forward。复用原坐标映射和评价函数。输入格点检查用于防止把其他分辨率的预测误套成四子格；原PCK复现与oracle不劣关系用于发现坐标、块映射或结果文件错配。

汇总完整train/val、visibility和clip，报告实际与oracle的PCK8/16/32、上述三类数量及同GT块数量。若额外报告检测，则存在分数和阈值固定，明确这是使用GT的定位oracle结果，不能与真实模型成绩混为一列。

小型测试包含保持原命中、块内可恢复、跨GT块边界仍可达、四子格均不可达，以及VC0坐标不变；不重新执行训练测试或全仓检查。

实现见[分析脚本](../../scripts/analyze_tennis_subcell.py)，复用原坐标转换及评价函数；[一项综合几何测试](../../tests/test_subcell_diagnostic.py)已通过。正式分析使用以下命令，结果单独保存于原run的subcell_diagnostic.json，不覆盖模型预测。

```bash
python -m unittest discover -s tests -p 'test_subcell_diagnostic.py'
python scripts/analyze_tennis_subcell.py --run outputs/full_heatmap/dino_prefix_seed0
```

## 它能改变什么决定

若块内可恢复部分很大，说明应继续检验细位置读出，而不是把这些错误直接归为选不到粗位置；**它不证明现有特征包含足够信息让模型学会该选择**。若该部分很小，则仅在固定预测块内改变四个输出的选择不足以解释主要差距。

该oracle只是固定实际粗块之后的几何上限，不是所有新head、连续坐标或高分辨率结构的性能上限。当前粗块由所有细格logit的全局argmax间接选出；改变子格打分也可能改变粗块选择，两者在真实模型内并非独立决策阶段。

无论结果如何，都不改变正在训练的真实历史/重复当前帧主要对照，不据oracle直接增加新分支、监督或motion模块；后续具体改动还必须由可学习证据与公平对照支持。
