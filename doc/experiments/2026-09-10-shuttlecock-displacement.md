# Shuttlecock 训练侧标签中心位移：跨球种前的运动压力核对

日期：2026-09-10。状态：已完成。协议：[Shuttlecock 开发范围与标签位移诊断](../protocols/shuttlecock-development-motion-v1.md)。本轮只做标签与已有视频元数据诊断，不训练模型。

## 假设与判别依据

待检验的直接假设是：Shuttlecock 是否比 Tennis 提供更大的绝对帧间中心位移压力，从而支持扩大对应搜索范围。判别量是同一 rally 内、原始 `Frame` 精确相差 Δ=1/2/4 且双端均为合法可见坐标的中心位移。报告原图 L2 分位数、L∞ 方形窗口覆盖，以及映射到 36×64 网格后的方形 R2/R4/R8 覆盖。

这些覆盖率只回答真实历史位置是否落入以真实当前位置为中心的几何窗口，不包含查询位置误差、特征可辨性、背景竞争和候选漏检，不能称为匹配成功率。数据没有可信的逐帧球尺寸，因此不计算或报告 `rho`。

## 实际范围与运行

开发划分在统计前固定：训练为 `Professional/match1…20` 与 `Amateur/match1…3`，验证保留 `Professional/match21…23`，Test 保留原发布测试集。一个 MP4 视为一个发布 rally，配对键包含来源、match、rally 和原始 `Frame`，不跨 rally，也不删除不可见帧后重编号。

本轮读取训练 CSV 一次；验证只读取已有 `verification.tsv` 中的路径与元数据，完全不打开验证位置 CSV；Test 的元数据条目在汇总前被排除，不打开其位置 CSV 或修正版标签。`development_rallies.csv` 含 18 个验证 rally 的元数据，只表示开发划分被明确记录，不表示使用验证标签调参。

实际命令：

```bash
/home/zshyc/miniforge3/envs/zshihyc/bin/python \
  scripts/analyze_shuttlecock_displacement.py \
  --output outputs/shuttlecock/development_motion
```

产物为：

- `outputs/shuttlecock/development_motion/summary.json`
- `outputs/shuttlecock/development_motion/development_rallies.csv`

统计覆盖 154 个训练 rally 和 18 个验证 manifest 条目。训练 CSV 共 69,791 行，其中 60,639 行为合法可见位置，9,152 行为 `Visibility=0` 的 `not_visible`，未发现非法 visibility 或越界/非有限可见坐标。训练视频在最后一个 CSV `Frame` 之后共有 352 个未标注尾帧；这些帧没有补成不可见或负例。

尾帧最初曾按 `nb_frames-csv_rows` 计算，这会把 CSV 内部缺帧误计为尾帧。综合测试用“内部缺 Frame3、视频尾部只缺 Frame7”的样例确认旧实现返回 2 而正确值为 1；修正为 `max(0, nb_frames-last_frame-1)` 后，标准库测试通过。已有真实 manifest 按新公式仍为 352，因此没有重复运行完整位移统计。

## 总体结果

| Δ | 合法位置对 | L2 P50 / P90 / P99 / 最大值（原像素） | 原图 L∞ R20 / R40 / R80 / R160 覆盖 | 36×64 R2 / R4 / R8 覆盖 |
|---:|---:|---|---|---|
| 1 | 58,961 | 8.94 / 23.32 / 60.83 / 474.35 | 88.62% / 97.63% / 99.70% / 99.98% | 98.53% / 99.81% / 99.99% |
| 2 | 58,199 | 17.46 / 46.00 / 111.22 / 481.07 | 61.98% / 88.75% / 97.91% / 99.86% | 92.78% / 98.44% / 99.90% |
| 4 | 57,151 | 34.13 / 88.77 / 191.45 / 494.84 | 32.12% / 62.76% / 89.58% / 98.47% | 72.16% / 91.87% / 98.73% |

相邻帧在 native 网格上用 R2 已覆盖 98.53% 的双端合法位置对；因此，这份数据不支持把“绝大多数相邻帧真实位移超出小局部窗口”作为默认动机。Δ=4 时 R2 覆盖降至 72.16%，R4 仍覆盖 91.87%，说明增加时间间隔会带来可测的搜索范围压力，但剩余难点仍必须与匹配混淆和观测质量分开验证。

最大值接近 500 像素，但尚未逐例视觉核对。它可能受真实快速运动、相机变化、标注跳变或其他发布条件影响，不能据此宣称数据中已经确认了实际超高速羽毛球事件；当前更稳健的证据是中位数、P90/P99 与覆盖曲线。

## 来源与平均 FPS 条件

| 条件 | Δ1 对数 | Δ1 L2 P50 / P90 | Δ4 对数 | Δ4 L2 P50 / P90 / P99 | Δ4 native R4 |

| Professional | 50,611 | 9.22 / 24.35 | 49,157 | 36.24 / 93.09 / 198.35 | 90.88% |
| Amateur | 8,350 | 7.07 / 16.28 | 7,994 | 26.40 / 60.80 / 113.64 | 97.95% |
| 25 FPS | 14,133 | 11.05 / 27.29 | 13,558 | 42.01 / 105.12 / 213.30 | 87.86% |
| 29 FPS | 2,519 | 8.00 / 24.62 | 2,463 | 30.27 / 95.30 / 188.13 | 90.13% |
| 29.97 FPS | 18,105 | 9.43 / 23.85 | 17,650 | 37.05 / 90.56 / 195.43 | 91.38% |
| 30 FPS | 24,204 | 7.28 / 19.92 | 23,480 | 29.43 / 75.43 / 166.87 | 94.73% |

25 FPS 组在 Δ=4 上表现出更大的位移分位数和更低的 R4 覆盖，符合更长平均帧间时间可能增大位移的方向，但各 FPS 组同时混合不同比赛、镜头、来源和场景，不能把组间差异解释成帧率的因果效应。Professional 与 Amateur 的差异也不能自动归因于竞技水平。

## 与 Tennis 训练侧的可比结论

对比采用 `outputs/spatial_probe/displacement.json` 的 Tennis game1–6 训练侧，避免把 Shuttlecock 训练结果与 Tennis game7 验证结果混在一起：

| 数据训练侧 | Δ1 L2 P50 / P90 / P99 | Δ2 L2 P50 / P90 / P99 | Δ4 L2 P50 / P90 / P99 |
|---|---|---|---|
| Shuttlecock | 8.94 / 23.32 / 60.83 | 17.46 / 46.00 / 111.22 | 34.13 / 88.77 / 191.45 |
| Tennis | 11.05 / 31.30 / 60.42 | 21.59 / 60.37 / 111.88 | 42.30 / 115.74 / 201.45 |

Shuttlecock 的绝对相邻位移并未整体大于 Tennis：Δ1 的中位数与 P90 均更小，Δ2/4 也呈相同方向；Δ1 P99 两者接近。由此不能再用“羽毛球天然具有更大的绝对帧间位移”作为跨球种验证的既定事实。Shuttlecock 仍可能因目标更小、模糊、遮挡、背景和可见性模式而更难，但这些需要后续模型误差与条件标注来证明，不能由中心位移统计代替。

## 判断与下一步

这次诊断支持保留多时间间隔和有限局部窗口的实验设计：相邻帧先用小范围建立对应基线，Δ=2/4 再检验扩大范围是否在背景竞争成本下带来净收益。它不支持直接上高分辨率全局 all-to-all 搜索，也不支持把几何覆盖当作模型已经能找到球。

后续跨球种实验应继续保持真实 rally 边界和原始 Frame，单独报告 FPS/来源条件，并先验证 tiny-ball 特征可读性与真实对应成功率。若要解释极端位移样本，需先对相关帧及标注做有针对性的视觉核对；在此之前不以最大值支撑论文中的“超高速”论断。
