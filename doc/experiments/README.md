# 实验记录

这里记录具体实验想检验什么、实际如何运行、结果是什么，以及结果支持或否定了什么。尚未运行的设计必须明确标为计划，不能因为有记录文件就称实验完成。

一个研究问题一份 Markdown，例如 `2026-09-12-backbone-readout.md`。同一问题下的多个 seed、层数或 baseline 可以放在同一份记录中，用实际输出目录区分运行；不为每个运行预建独立文档。

## 文件格式

```markdown
# 实验问题

日期：YYYY-MM-DD
状态：计划 / 运行中 / 已完成 / 已停止
协议：实际采用的 doc/protocols/ 文件相对链接

## 假设与判别依据
要区分哪两种解释；怎样的结果会推翻当前偏好。
实验自变量、对照与保持一致的条件。

## 实际设置与运行
代码版本或具体改动、数据/标签版本、配置路径、预训练权重版本。
冻结/微调方式、输入分辨率和时序范围、seed、实际设备与环境。
项目根目录下执行的真实命令，以及输出/日志位置。

## 结果
未运行时直接写未运行，不填模拟分数。
运行后列实际指标与适用范围；耗时/显存只报告有实际测量的项目。
失败运行记录原因和处理，不静默从比较中删除。

## 判断与下一步
结果支持什么、不能说明什么；继续、停止或修改哪个研究决定。
有关图表、运行产物或后续文档的链接。
```

正式比较引用锁定协议。小型探索若尚无协议，可以写“探索，协议未锁定”，同时写清用到的数据、输入和标签条件；这种结果不能冒充正式 benchmark。

完整日志、预测、checkpoint 和缓存留在 `outputs/` 等实际输出目录，文档仅保留解释结论所需的小表、图和路径。输出目录按研究主题与运行名组织即可，不新增实验数据库或内容指纹体系。
