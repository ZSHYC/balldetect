# BlurBall因果中点定位：已确认内部时间边界

状态：已锁定；版本：v2；锁定日期：2026-09-11。

替代[v1](blurball-causal-midpoint-v1.md)的窗口部分，其他模型、预处理、划分、标签、4/8/16px严格容差、两种F1、选优、30epoch、seed0和半长度分组均保持。本版本源于[实际源视频连续性复核](../experiments/2026-09-11-blurball-continuity.md)，不是根据验证模型表现删数据或改训练超参。

## 为什么必须换版本

源match17中的rally001、004、006各有一个已确认同视角时间突变。容器PTS连续且视频文件名叫rally，不能保证其内每一步都代表连续场景时间。v1启动的训练未完成epoch1即终止，保留中断产物，不作为正式结果或新初始化。

原始Frame、rally标识、像素、theta/l、位置与visibility保留。每个边界将原rally在时间上分成两段，只允许同段`[t−2,t−1,t]`。首个新段合法目标分别159、59、769；不能把边界后两帧重新编号、补历史或借旧段帧。

RGB及原始metadata继续使用`data/cache/blurball/rgb_512x288_all_h2/`，不重解码，不覆盖原窗口账本。训练入口读取边界CSV，对原窗口做确定性剔除，并在每次config保存边界原文和被排除目标身份；之后预测复核从该run保存的边界构造同一目标集。

实际训练目标38,854，验证目标14,192。源53,818帧均保留，原766个rally边缘目标之外新增6个训练目标边界排除。验证数据与任何最终测试均未因这一修订发生改动。

同格三帧模型无跨窗口时序状态；其输入已按边界限制。今后若引入时序缓存、轨迹状态或更长窗口，也必须使用这份分段边界重置，不能只照原rally字符串继承状态。

## 证据与验证边界

本次以已知641.9px异常为触发，检查同来源match17的6个rally，每rally最大6项低分辨率像素变化仅用于定位候选，最终通过可观察画面判断；字幕变化不作为时间边界。三个边界均有独立视觉复核，部分读取原始分辨率帧确认。没有训练切镜模型，也没有声称这个候选检索穷尽了全部视频的所有剪辑。

一个合成窗口检查确认原rally隔离、跨内部边界的两窗排除、边界后第三帧恢复，以及错误边界不能静默忽略。实际元数据恰好排除表中6个目标，38,854/14,192计数通过。模型和loss未改，无需再跑同一单batch梯度检查；重新训练从相同官方权重和seed0新头开始，epoch0应与中断运行的相同验证集一致。

2026-09-11实施补充：公共量化函数已修复合法图像末端小数坐标的格索引越界，先验证原图坐标有效，再取最近边缘格；原始坐标不裁剪。实际仅一个未用于loss的验证目标格改变，全部训练监督、预测坐标和评价不变，因此该修复不改变本协议或重新启动训练。细节及理想量化误差见[实验记录](../experiments/2026-09-11-blurball-midpoint.md#理想网格量化与合法边缘坐标修复)。
