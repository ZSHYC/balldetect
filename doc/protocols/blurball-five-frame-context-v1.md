# BlurBall五帧因果与双向视觉对照

日期：2026-09-13。状态：开发协议v1，正式运行前锁定。不是论文最终benchmark。

依据：[物理与多帧分析](../research/2026-09-13-ball-physics-feasibility.md)。用户明确允许更多帧与未来帧。本轮先检验未来视觉观测的价值，不加入新的物理损失，避免把输入增加与物理机制混为一谈。

## 要区分的解释

现有因果三帧模型的背景竞争和错误延续，是否能在同帧数、同参数、同训练目标的条件下，由目标之后的真实观测得到改善？

两个新条件均为共享DINOv3 ConvNeXt-Tiny stages0–1的五帧视觉模型，沿用cross-address非线性空间读出。因果输入为`t−4:t → t`，双向输入为`t−2:t+2 → t`。两者首尾总跨度都是四个原帧间隔，只改变目标在窗口中的位置及前后观测分配；这仍可能改变事件/遮挡覆盖，不能称为纯物理方向干预。

现有三帧cross的最佳权重与预测保留，作为已有系统参考，不重训。三帧对五帧同时改变输入量与读出通道，不单独承担“未来帧的独立增量”归因。三帧双向是后续有必要考虑的更省计算竞争模型；本轮GT拟合已经提示其可能很强，不能因为五帧网络有效就声称五帧必需。

## 输入、目标与数据

复用`data/cache/blurball/rgb_512x288_all_h2/`的紧凑逐帧RGB。目录名中的h2描述原缓存目标索引来源，不限制底层帧数组只能组成三帧。

训练match00–17，开发验证match18–21，最终match22–25保持封存。目标候选来自原metadata三帧末帧集合，按原始`match/rally/frame`查询新上下文，排除缺失源帧及`configs/blurball_continuity_boundaries.csv`中的内部边界。不得用visibility选择训练窗口，不越rally、不以行号代替原帧号。

因果五帧与双向五帧各自然可用训练38,222、验证14,052个目标，但对应身份不同。**两臂共同使用交集：训练37,590、验证13,912。** 两臂的当前标签、顺序及每轮随机排列一致；不在各自自然集合上训练后声称完全同条件。

相对原合法三帧目标38,854/14,192，共同目标减少训练1,264（约3.25%）、验证280（约1.97%）。来自合法时域与片段首尾支持要求，不按误差或visibility筛除。主要结果在共同目标上比较，同时报告此覆盖损失；不把共同目标的分数替代旧完整目标分数。

当前监督仍为可见拖影中点；V0使用既有可定位状态规则，不等于物理无球。仅训练/验证标签进入各自loss或评价，前后RGB为输入；未来GT不作为模型输入。五帧双向预测中间slot2，因果预测slot4。实际每条输入恰为五张原图，不串联三帧候选模型暗中增加原始时域。

## 模型与开发训练预算

共享官方DINOv3 ConvNeXt-Tiny预训练前缀，五帧分别编码，192通道/帧，共960通道；每帧独立归一化，读出沿用32隐藏通道的cross-address空间交互与8倍输出。既有三帧初始化路径保持原样，新两臂从同一随机种子建立相同形状、相同初始化的模型。

每臂12个**完整epoch**，seed0，batch4；每轮使用全部37,590个训练目标，不限制batch数。两臂共享AdamW、prefix学习率1e-5、head学习率3e-4、weight decay0.01、恒定学习率、float32及无增强。12轮是本轮开发预算：既有多组模型最佳集中于前几轮，本轮先在相同预算内取得结构判断；不称30轮，不宣称全部训练已收敛。若最佳接近预算末端并继续明显改善，应根据实际曲线另记预算延长，不能据早期偏好选择性终止一臂。

选优沿用local detection F1@4，平局用F1@8，再取更早轮次，包括epoch0。训练完成后从best导出全量共同训练/验证预测；保留last及优化器/RNG用于事实追溯。既有工具的resume只恢复已经完成轮次，新增配置不覆盖旧运行。

这里选优的空间坐标沿用训练入口的argmax；“local detection”指本项目的FP/FN计数口径，不代表局部重心坐标。best固定后，两臂均采用既有15×15、温度1的局部重心读出，保留原q，同时记录argmax与局部结果。评价入口验证argmax和输出状态可复现；不按局部结果重新选epoch或调半径。

GPU与其他本地研究任务共享；新两臂顺序执行。batch4需在真实输入上确认显存与梯度，再启动。此资源条件下训练墙钟时间仅作本次实际成本，不能作为独占GPU速度benchmark。

## 指标、归因与继续条件

报告共同验证目标的原图严格PCK@4/8/16、local F1@4/8、逐比赛结果、半拖影长度分组与实际可定位状态。复用保存预测做成对救回/破坏，不为改变评价阈值重复forward。主要比较为center5对causal5，旧cross仅在共同目标子集上给出参考及其训练集合不同的限制。

若双向在精定位和检测上都有有意义的净收益，且不是单一比赛独占，继续分析被救回目标的前后证据以及失败类型，再决定是否引入物理信息。若只有总体小幅波动、位置变好但检测变差或收益高度依赖比赛，则保留这些事实，先检查身份、置信度与时域，不直接堆物理模块。

不把一次seed、四场开发验证或GT轨迹拟合当作论文稳定增益。后续要检验的物理机制必须与同一个双向视觉基线共享帧数、前瞻、目标及预算；三帧双向低成本竞争解释不能遗漏。

## 时间与效率边界

输入时域与前瞻按真实PTS报告。双向五帧等待两帧未来，预录视频可离线运行；因果五帧没有未来等待但仍有计算延迟。片段首尾支持不足已进入共同目标覆盖统计。

不解码新视频，不保存重复窗口RGB。训练复用mmap和单批CPU预取，骨干更新时正常重新提特征；验证沿用每batch对重叠源帧去重后提特征。不引入跨参数更新的失效特征缓存。本轮不声称已消除跨验证batch的全部重复编码，也不把训练缓存速度当作在线端到端速度。

## 针对性验证

窗口测试需捕获中心标签误取末帧、跨缺帧/rally/内部边界及标签过滤输入。模型验证需确认五帧输出、目标slot与梯度有效，并保留默认三帧构造和旧恢复路径。正式运行前做真实batch的输出/有限梯度/显存检查，不重复解码或重验数据包。

运行入口沿用`scripts/train_blurball_midpoint.py`，新增`--window causal5|center5`；正式命令、代码提交和实际输出位置写入本轮实验记录。
