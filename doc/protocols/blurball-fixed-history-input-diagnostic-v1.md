# BlurBall固定权重历史输入诊断

日期：2026-09-13。状态：方案运行前固定，已执行；结果见[实验记录](../experiments/2026-09-13-blurball-history-input-probe.md)。性质：开发集输入干预，不是新的训练基线或性能排名。

依据：[空间交互失败拆分](../experiments/2026-09-13-blurball-spatial-failures.md)。match21的cross新增远错位多数被拒绝，尚不能归因于搜索范围或输入信息消失。本诊断只问：固定已训练网络时，原输入历史对这些失败有何作用？

## 唯一干预与不变项

- 模型分别固定为same best4、cross best3；不更新任何参数，不重新选优。
- 对每个合法目标t，把输入`[t−2,t−1,t]`改为`[t,t,t]`。原当前帧、目标、真实索引和片段边界不变，零未来帧。
- 复用512×288逐帧RGB缓存，完整14,192个验证目标、全部match18–21，batch8，float32模型、float64重心期望；最终match22–25不读取。
- 每模型只新增一次完整干预forward，批内重复帧只encode一次。该复用仅用于固定eval网络，不迁移到参数更新中的训练。原输入预测直接复用已保存结果。
- 同一次logits取原argmax及固定15×15/T1重心，二者共用本次干预产生的q与0.5判定。q允许与原输入变化；不能沿用旧q掩盖干预对输出状态的影响。

## 固定群体与评价

沿用全部目标、四场、l、历史可见状态和d1/d2组；运动分组仍由真实历史标签计算，不能因输入槽重复而把位移都重新算成零。

额外固定两个match21群体，仅由原same/cross固定重心预测定义：same误差<16、cross≥16的202个破坏目标，以及same≥16、cross<16的74个救回目标。原图严格容差与V1条件不变；看见干预输出后不重定义它们。

对两模型、两读出、全部群体报告原输入与干预后的PCK@4/@16、本地F1、q对应的输出状态、救回与破坏。分析固定202例时同时报告同模型全体验证的代价，不把条件修复率当整体提升；固定74例提供相反方向的对照。

## 解释与下一步规则

这相对于固定函数是明确的输入干预，但重复当前帧改变了训练输入分布。输出变化表明输入历史的作用，不能直接等价为motion correspondence的作用；可能涉及外观、遮挡、顺序、归一化或置信状态。没有变化也不能证明网络不用历史。

若固定破坏例被重复当前帧修复，只支持这些错误对历史输入敏感，下一步应比较何种历史证据被利用；不据此直接关闭历史。若干预仍不能修复多数固定例，则不以这组退步为由直接扩大时序搜索网络，而先检查固定图像证据与表征读出。全体若严重下降，明确保留历史的总体价值与局部代价，不改称干预是更强模型。

这不替代既有的重新训练repeat_current控制，不启动新的长训练、不调阈值、不扫描温度/窗口，也不改变前一空间交互对照的取舍。

## 验证与产物

共享批读出抽取先用小例核对三槽顺序、重复当前、尾batch、argmax邻域和q与显式路径一致，并复用既有局部读出测试。正式运行先以每模型原输入的首个真实batch复现保存argmax及q，再处理全体干预目标；失败则修读取路径，不解释干预指标。

入口：`scripts/probe_blurball_history_input.py`。产物位于 `outputs/blurball/spatial_interaction/history_input_probe/`：两模型的两种预测CSV、紧凑局部logit缓存、含原模型与代码版本的完整分组结果。缓存用于后续CPU分析，不保存重复RGB窗口或全图热图。记录实际前向耗时与显存，不把该诊断速度当部署吞吐。
