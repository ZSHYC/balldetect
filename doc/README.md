# 文档导航与组织规范

`doc/` 保存从研究问题到论文证据的文字记录：为什么研究、文献说明了什么、实验遵循什么协议、实际得到什么结果，以及据此作出什么判断。目录统一使用 `doc/`，不再并行维护 `docs/` 或根目录的 `research_notes/`。

## 各目录放什么

| 位置 | 放什么 | 写入时机 | 内容边界 |
|---|---|---|---|
| `research/` | 立项蓝图、综合审查、机制分析、候选方法与研究取舍 | 形成一个值得讨论的研究问题或实质修订时 | 是研究论证；不能把假设写成实测结果 |
| `literature/` | 按问题组织的论文证据、近邻方法比较、检索范围与阅读限制 | 文献会影响当前设计或创新判断时 | 保存出处；不重复抄整篇综合报告 |
| `protocols/` | 数据划分、标签映射、合法输入窗口、评价指标和比较条件 | 第一组正式实验前，或协议需要实质调整时 | 是实验执行依据；与文献中“建议做什么”分开 |
| `experiments/` | 一个研究假设对应的计划、运行条件、结果、失败与结论 | 准备或执行具体实验时 | 保留未运行/运行中/完成的区别；日志和权重只链接 |
| `progress/` | 某一阶段完成了什么、证据在哪里、接下来为什么做什么 | 有实质进展或研究判断变化时 | 是简短时间线，不复制完整报告和实验表 |

根目录 `README.md` 是项目入口；`AGENTS.md` 是长期协作约束。数据源自身的 README、标注说明、采集记录和异常表继续随数据保存在 `data/`，这里通过链接引用，不维护第二份数据统计。

预训练权重清单、位置与架构对应关系保存在 [models/README.md](../models/README.md)，权重二进制文件不放入 `doc/`。

论文正式写作开始时再创建 `paper/`，保存稿件、参考文献和投稿相关文字；出现需要保留的图表时再创建 `assets/<文档主题>/`。本次不创建空的论文草稿、图片目录或模板文件集合。

## 推荐阅读顺序

1. 先读[第二轮研究总纲](research/高速微小球运动表征_第二轮第一性原理与对抗性研究总纲_2026-09-10.md)，理解最近一轮综合论证及尚未验证的问题。
2. 需要追溯原始设想时读[立项蓝图](research/高速微小球运动表征_论文立项与实验蓝图_2026-09-09.md)，需要了解第一轮修订依据时读[研究审查与反馈](research/高速微小球运动表征_研究审查与反馈_2026-09-09.md)。
3. 针对正在做的研究决策查阅对应文献笔记，不要求每次重读全部材料。
4. 实际用数据前读[数据说明](../data/README.md)；正式实验采用明确的[协议](protocols/README.md)，运行与判断写入[实验记录](experiments/README.md)。

研究总纲是论证材料，不是已经批准的最终模型。较新的文档只在明确修订的论点上取代旧论点；不能据文件日期把所有旧来源都视为失效。

## 命名与书写格式

所有新文档使用 UTF-8 Markdown。新增正文使用中文，论文题名、代码标识和上游原文按用途保留。默认不增加 YAML front matter、文档构建系统、自动编号服务或元数据解析脚本。

| 类型 | 新文件名示例 | 约定 |
|---|---|---|
| 研究论证 | `research/2026-09-12-spatial-evidence.md` | 日期是本次论证形成日期；标题用中文说明问题 |
| 文献专题 | `literature/2026-09-12-large-displacement.md` | 文件名按研究问题命名，不每篇论文强制建一文件 |
| 实验协议 | `protocols/tennis-game-level-v1.md` | 只有正式锁定并出现不兼容更改才递增版本 |
| 实验记录 | `experiments/2026-09-12-backbone-readout.md` | 一个问题一份记录，可含该问题下多个运行 |
| 阶段进展 | `progress/2026-09-12-feature-probes.md` | 一个有实质变化的阶段一份；不是每条命令一份 |

上述未来日期和文件名只是命名示例，不表示已经安排或运行实验。现有十份文档保留原文件名，不为统一外观强行改名。

新研究论证和文献笔记可以从以下简短格式起步；只填写实际适用的内容，不保留空栏目凑格式：

```markdown
# 中文标题

日期：YYYY-MM-DD
性质：研究论证 / 文献证据
范围：这份文档回答哪个具体问题；相关前文用相对链接给出。

## 结论或当前判断
先写判断，并区分来源事实、推论和待验证假设。

## 依据与分析
研究论证：失败机制、竞争解释、什么结果会推翻判断。
文献证据：原始链接、论文版本/日期、实际阅读范围、机制与本项目的关系。

## 对下一步的影响
因此采用、放弃或暂缓什么；仍缺少哪一项关键证据。
```

实验协议和实验记录使用各自 README 中的专用格式。进展记录只需包含日期、阶段目标、已完成内容及证据链接、未解决问题和下一步判断；不复制文献表、配置全文或训练日志。

## 维护方式

- 一份材料有一个归属：文献事实在专题笔记，执行约定在协议，实际结果在实验记录，进展只作摘要和链接。
- 新的整体判断写新的研究文档并注明修订哪篇；不把旧假设改成仿佛从来正确的结论。普通错字和失效相对路径可直接修正。
- 实验开始前可以在同一记录内完善计划；开始运行后保留当时的设定，后续改变另记运行或关联新协议，不用覆盖方式隐藏失败和负结果。
- 链接使用相对路径，图表链接到实际文件；不写个人机器绝对路径作为仓库内导航。命令以项目根目录为工作目录，并注明实际环境条件。
- `doc/` 保存文字和少量用于阅读的图表；原视频、数据标签、完整日志、缓存和权重留在对应数据/输出位置。不要复制上游 README 来填满目录。
- 移动文档时同步调整链接与导航。本次目录变化只需检查本地引用是否断开；不触发下载、哈希、文献重检或模型训练。
