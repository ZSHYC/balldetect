## 1. 总体判断

**这个方向值得做，但目前最缺的不是模型模块，而是一个能够排除替代解释的核心发现。**现代预训练骨干、几像素空间支持、较大帧间位移、有限计算预算，这些条件构成了有价值的研究场景；它们的组合本身还不能证明存在一个新的算法问题或新的解决机制。

现有蓝图已经很好地约束了任务，也意识到“换骨干”“加 motion”“加 gate”不足以构成贡献。需要再向前一步：不只罗列不能声称什么，而要找出**哪一种具体时空证据，在何种条件下被哪一步处理削弱，最简单的替代方法为什么没有解决，新的机制究竟改变了什么**。

我建议继续这个项目，同时对原稿作三项实质调整：

1. **把“显式 correspondence 应当是主路线”降为竞争假设。**它很合理，但单球定位也可能通过强空间检测、廉价时序融合或检测分数上的轨迹推理达到同样效果。显式匹配必须赢得它的计算预算。
2. **把“两端 top-k 候选匹配”降为待检验原型。**这条路线可能在最需要时序帮助的帧上提前丢掉球，也可能退化成两个单帧检测器之间的配对。
3. **把方法开发前的验收，从“对应有提升”改为“时序证据有独立定位价值”。**对应排名、可读性、定位精度和成本必须形成相互支持的证据链。

我的当前判断如下，置信度是对判断本身的把握，并非论文录用概率：

| 判断 | 置信度 | 依据与限制 |
|---|---|---|
| 连续 RGB 体育片段中的高速小球定位值得研究 | 高 | 直接任务文献与公开标签支持；不需要扩大到切镜 |
| 不同空间尺度与位移搜索尺度可能存在冲突 | 高 | 机制上成立，Devon/SCV 等已有明确先例；不是新的发现 |
| DINOv3 必然改善小球定位 | 不支持 | 架构和权重存在，不等于该任务性能已经成立 |
| 当前蓝图的稀疏候选关系模块已经具有足够新颖性 | 不支持 | 与稀疏相关、可变形采样、候选跟踪和置信度方法有明显交集 |
| 有望通过严格诊断收敛出有研究价值的机制 | 中 | 有合理切入点，但缺真实数据上的失效与可重复收益 |
| 现阶段可以保证 CCF B 或以上录用 | 不支持 | 尚无实验、机制差异和审稿证据，不能据文档完整度推断 |

## 2. 对原蓝图的具体评价

### 2.1 应保留的设计边界

原稿第 01、06–07、15–17 节的基本方向应保留：连续 clip/rally；不跨边界训练；缺标不等于无球；保留原始时间索引；现代骨干内归因；统一空间细节与未来帧预算；区分中心运动、稠密光流、曝光拖影与轨迹预测；计入完整推理成本。

这些是可信论文的必要基础，但不宜作为主要算法贡献逐项包装。尤其“不新增人工标注”应当成为一个贯穿所有实验的监督契约，而不是后续遇到困难时可以撤回的临时设定。

### 2.2 原稿最需要修订的地方

| 原稿位置 | 当前不足 | 建议修订 |
|---|---|---|
| §02、§03：tiny support 与 large displacement | 作为动机成立，但已有直接历史先例 | 补 Devon、SCV；从一般矛盾收窄到实测的具体失败 |
| §05、§10：多峰与稀疏关系 | 主要靠 MotionSqueeze/SELFY/QueryDet 审查，近邻仍不够直接 | 加 SCV、现代相关体采样、SuperGlue 式拒配边界 |
| §08：球中心上的对应探针 | 查询已知是球时，目标帧独立检测就可能取得好成绩 | 加入 query-blind 对照与检测分数可分解对照 |
| §11：两端高召回候选 | 全体平均候选召回可能掩盖单帧定位失败集合中的低覆盖 | 重点测“当前外观失败且历史有证据”的覆盖 |
| §11：候选关系再回写热图 | 可能只是重排已有峰，未提供新的空间证据 | 区分救回漏检、改善坐标、抑制误报三种收益 |
| §12：对应监督 | 同一球的中心对不保证学习到实例对应或纯 motion | 用独立检测、分数轨迹模型、辅助监督对照拆解 |
| §12：null / 无可靠匹配 | 缺少可直接从现有标签获得的可靠性真值定义 | 区分不可见、候选漏失、集合内拒配、使用后变差 |
| §14：固定 512×288 起步 | 若观测已经被缩放破坏，小规模跑通也可能得出错误否定 | 先做原图—输入的证据抽查和两个分辨率对照 |
| §15：两个 2×2 | 有必要，但“无新 motion”含义不够清楚 | 扩展成旧/新骨干 × 无时序/强简单时序/新机制 |
| §16：分桶与反事实 | 大位移与模糊、可见性、事件类型可能混杂 | 尽量采用同一目标帧改变上下文间隔的配对试验 |
| §19、§23：优先执行路线 A | 在定位增量价值未确立前仍有架构先行倾向 | 先回答 motion 何时有用，再决定采样、匹配或监督路线 |

这不是推翻原稿。原稿已经避免了不少常见错误；进一步提升质量的关键，是给最喜欢的路线安排有资格击败它的对照。

## 3. 从成像与任务出发，而不是从模块出发

### 3.1 被定位的“球中心”首先是一个标注量

理想化图像可写为：

\[
I_t=\mathcal Q\!\left[\mathcal R\!\left(\int w_t(\tau)L(\cdot,\tau)\,d\tau\right)\right]+\epsilon_t.
\]

这里分别包含曝光积分、空间采样/缩放、压缩或量化及噪声。该式用于分析，不要求第一版估计所有成像参数。

但监督目标 \(p_t\) 由数据标注约定决定：它可能是拖影几何中心、某个可辨认亮斑位置，或特定协议的前缘坐标。若曝光中运动非匀速、轨迹弯曲或发生遮挡，拖影几何中心未必等于曝光中点的瞬时物理球心。BlurBall 的位置与拖影定义应按原文统一；不应把不同坐标定义下的误差混在一起解释为 motion 改善。[BlurBall 原文](https://arxiv.org/html/2509.18387v2)

**研究目标应先写成“预测公开协议定义的二维球位置”，再说明它与物理中心的关系。**这不会削弱论文，反而避免声称标签无法验证的物理精度。

### 3.2 原始观测损失与特征读出困难必须分开

如果缩放把球与背景混合到无法区分，后续网络无法保证恢复该帧独有的视觉证据；它仍可能根据邻帧与场景先验估计位置，但那是条件推断。

反过来，球小于一个 patch，不表示它对 token 完全没有影响。Patch embedding 是有通道的映射，不是“每个 patch 只留一个颜色”；细微位置也可能编码在通道变化里。简单探针失败只说明在该读出能力、训练样本和优化条件下难以利用，不能证明信息论上的彻底消失。

因此应区分：

| 层次 | 可以问什么 | 不应直接推出什么 |
|---|---|---|
| 原始视频 | 可见球是否有稳定像素证据 | 肉眼难看见就完全不可定位 |
| Resize 后输入 | 采样和压缩使证据削弱多少 | 神经网络可以无条件恢复全部细节 |
| 骨干各层 | 相同探针能否定位或区分球/背景 | 探针差就意味着信息绝对不存在 |
| 搜索集合 | 真对应是否被实际查询 | 名义搜索范围覆盖就一定采到球 |
| 关系压缩 | 真峰是否被平均、筛除或背景峰压倒 | 多个峰天然代表真实不确定性 |
| 最终读出 | 有用对应是否改变正确定位 | 对应指标改善必然带来任务改善 |

### 3.3 \(\rho\) 有解释力，但不是任务难度的充分统计量

保留：

\[
q=d/s,\qquad \rho=D/d.
\]

但相同 \(q,\rho\) 下，任务难度可以完全不同。纯色背景上的一个亮球可能很容易定位；背景有十几个相似反光点则可能很难。模糊、遮挡、局部对比、相机运动、编码噪声和标签误差也会影响结果。

至少还应考虑四个分析维度：可观察的目标对比；候选混淆程度；帧间外观变化；标注位置相对视觉结构的稳定性。没有现成标签时，它们可以是明确标注的代理诊断，不能伪装成新的人工真值。

多数中心点数据没有真实 \(d\)，这一限制原稿已经说明，应保留。主分析使用原图/标准坐标中的位移 \(D\)、真实时间间隔 \(\Delta\tau\) 和 BlurBall 的已有模糊属性。不可用高斯热图半径替代球尺寸。

一个额外细节是：等比 resize 同时缩放 \(D\) 与 \(d\)，所以理想几何下 \(\rho\) 不变；但 \(q\)、对比和量化误差会变化。因此，提高分辨率后变好不直接证明解决了“更大的相对位移”，可能只是保留了更多空间证据。

### 3.4 相邻帧位移大，不等于应该永远选最短时间间隔

短间隔通常让搜索更容易，却可能使球的变化弱于压缩与亮度噪声。长间隔可增加可辨认变化，也会增加遮挡、外观改变和运动突变。

值得研究的是**时间间隔与空间证据的联合有效区间**，而不是简单假定三帧优于两帧、五帧优于三帧。第一版可以只比较少量固定间隔；尚不需要增加一个学习式选帧网络。

输入不同 FPS 的视频时，同样的帧数和索引间隔不等于相同时间跨度。对跨球种实验尤其需要明确这一点。

### 3.5 三种 motion 的价值不能混为一谈

**视觉补充价值：**当前球弱，邻帧保留了可利用的视觉证据，经过对齐帮助当前帧定位。

**歧义消除价值：**当前帧有多个相似候选，跨帧证据帮助选择正确位置。

**动态先验价值：**当前没有可靠证据，过去轨迹使某些位置更可能。

三者都能提高系统指标，但支持的论文主张不同。若收益主要来自第三项，论文应主要讨论动态推断或轨迹先验；若要主张 correspondence representation，应优先证明前两项。

## 4. 最重要的新质疑：单球监督允许“伪对应”捷径

### 4.1 两帧分别找到球，不等于利用了跨帧关系

假设每帧只有一个标注球，当前与历史候选的单帧球分数分别为 \(a_t(u)\)、\(a_j(v)\)。构造：

\[
C_{\mathrm{sep}}(u,v)=a_t(u)+a_j(v).
\]

对任意固定 \(u\)，沿 \(v\) 做 softmax 后，\(a_t(u)\) 完全抵消。模型只需在历史帧检测球，就能对所有“当前真球 query”给出正确历史匹配。

因此，一个只在 GT 球中心发起查询的 top-1 correspondence 指标，可能被完全不依赖 query 内容的方法拿到高分。这是根据任务结构构造的反例，不是说某篇现有论文已经被证实存在这种作弊。

类似地，训练特征可以把所有球位置映射到一个“球类别”方向，把背景映射到其他方向。在每帧单球的数据里，这可以取得很好的中心匹配，却不必包含比球检测更丰富的运动表示。

**这种解并不一定对任务无用，也不是训练违规。问题在于不能用它证明“学到了更好的实例对应、纯运动子空间或物理 motion”。**

### 4.2 应加入的三个对照

| 对照 | 最小形式 | 若与新方法接近，说明什么 |
|---|---|---|
| Query-blind 被检索端检测 | 所有 query 共用被检索帧的球分数排序；当前查询历史时，就是历史球分数 | 真中心匹配探针不足以证明跨帧关系 |
| 独立检测分数配对 | 两端 appearance scores 相加/相乘 | 候选图可能主要编码 ballness |
| 分数＋弱几何先验 | 检测分数加相同预算的位置/时间关系头 | 收益可能来自位置先验与候选重排 |

再加一个直接任务对照：在相同单帧 heatmap 上使用短窗轨迹推理，例如简单候选路径打分。它可以容许碰撞处突变，不必故意使用错误的强匀速模型。这个对照与特征级 motion 使用相同帧数、相同前瞻，不额外引入长时间历史。

### 4.3 怎样把探针设计得更有区分力

第一，查询不仅包含真球，也包含模型高分的错误候选。评价不能默认任意 query 都应该匹配历史球。对于非球查询，现成中心标签只能监督“不是本任务球的对应”，不能提供其真实背景光流。

第二，保持候选集合、坐标和 appearance scores 不变，只替换关系描述符，观察定位是否改变。应配合重新训练的简化模型，避免仅靠推理阶段破坏输入造成的分布外下降下结论。

第三，重点看当前外观困难、历史存在可信可见球的集合。若新方法只在两帧都很容易检测时改善匹配，可能没有解决定位的关键困难。

第四，允许结论更克制：中心监督支持的是**任务相关的球关系表示**。不强求证明一个完全与外观无关的 motion latent；对于无纹理、可遮挡、形变明显的球，外观与运动联合使用本来就合理。

## 5. 第二个关键质疑：候选召回必须在“需要被救回”的样本上测

### 5.1 两端稀疏化的条件上限

记 \(A_t\) 为当前候选集合覆盖真球，\(A_j\) 为历史候选集合覆盖真球。在关系分支只能连接已有候选、局部细化也无法到达集合之外时，正确球对进入关系分支的概率为：

\[
P(A_t\cap A_j)=P(A_t)P(A_j\mid A_t).
\]

它至多为两端覆盖率的较小值。不能未经验证把两个边际召回率相乘，因为同类背景、相同模糊与遮挡常使失败相关。

这个上限约束的是**候选关系路径**。若系统还有密集外观分支或可到达新位置的探索路径，它不是整个检测器召回的严格上限。论文中必须把这一适用条件写清，避免另一种过度断言。

### 5.2 全集 99% 候选召回仍可能没有研究价值

举一个纯说明性例子：空间基线在大部分帧已成功，仅一小部分困难帧失败。如果 top-k 候选恰好在这些困难帧漏球，那么很高的全集候选召回不会给 motion 分支留下多少救回空间。

应定义一个固定的参考集合：

\[
\mathcal H=\{t:\text{固定空间基线定位失败，且至少一个合法邻帧有可信可见球标签}\}.
\]

在 \(\mathcal H\) 上报告当前覆盖、历史覆盖、联合覆盖、最终救回率。困难集合由预先冻结的参考基线与规则产生；不能为每种方法分别挑不同困难帧，也不能只选新方法改善的例子。

### 5.3 比“两个 top-k 集合相乘”更值得先测的对照

**稀疏历史锚点 × 稠密当前细网格**应成为优先诊断对照。它保留历史有限候选，但不要求当前球先进入 top-k；因此可以直接检验当前端候选化是否过早丢弃了证据。

反方向“稠密当前 query × 稀疏历史 key”在计算形式上相同；从任务解释上，重点是当前所有位置仍有机会接收历史支持。它仍可能受历史漏检、描述符混淆和单球捷径影响，不能当成已经解决问题的新机制。

另一项便宜对照是在历史多个合法帧之间取候选并集，而不是默认扩大当前 top-k。它是否更有用取决于困难帧的失败是否相关、额外帧是否增加可用证据，以及时间预算是否公平。

## 6. 文献审查后必须收紧的新颖性边界

### 6.1 三个会明显改变立项判断的补漏

**Devon。**其原文已经明确讨论小目标快速移动时，多尺度降采样与粗到细估计的失败，并采用单一较高空间分辨率上的可变形代价体处理多尺度运动。这个先例直接约束“看得细同时找得远”的一般动机，早于现代视觉基础模型。[Devon，arXiv 1802.07351 / WACV 2020 版本](https://openaccess.thecvf.com/content_WACV_2020/papers/Lu_Devon_Deformable_Volume_Network_for_Learning_Optical_Flow_WACV_2020_paper.pdf)

**SCV / Learning Optical Flow from a Few Matches。**其引言与 §2 已涉及 small objects moving fast、较高分辨率、全局搜索范围及少量 top-k 相关项。保留相关分数和位移坐标、用多尺度编码压缩关系，也有明确先例。不能把“高分辨率全局少量候选”作为空白区域。[SCV，arXiv 2104.02166，正文 §1–2](https://arxiv.org/html/2104.02166)

**Efficient All-Pairs Correlation Volume Sampling for Optical Flow Estimation。**CVPR 2026 论文从实际采样需求与块稀疏实现改进 RAFT 数学算子的执行，说明高分辨率对应的瓶颈也可能来自算子实现，而不只是必须换一种表示。应避免仅以朴素全相关体作昂贵稻草人。[CVPR 2026 正式页面](https://openaccess.thecvf.com/content/CVPR2026/html/Briedis_Efficient_All-Pairs_Correlation_Volume_Sampling_for_Optical_Flow_Estimation_CVPR_2026_paper.html)

这些工作没有自动否定本项目，但把问题从“以前没有兼顾过这三件事”改成了：**在点监督、极弱球证据与定位预算下，已有搜索/压缩策略的哪种选择仍然不合适？**

### 6.2 机制—近邻—还需要证明什么

| 候选表述 | 必须面对的先例 | 仍可能值得验证的差异 |
|---|---|---|
| 加入便宜 motion module | TSM、GSM、GSF、TDN | 在共同骨干下，哪些位移/观测条件需要更明确的空间关系 |
| correlation 得到位移和置信度 | MotionSqueeze | 不是原始置信分数，而是任务中错误对应的具体来源与处理 |
| 保留对应分布或多个峰 | SELFY/STSS、SCV、MOSS | 哪些真球峰被过早压缩，以及保留后是否改善最终定位 |
| 单高分辨率多尺度搜索 | Devon | 搜索采样怎样避免跳过弱小支持区域 |
| 全局匹配加局部细化 | GMFlow、RAFT、FlowFormer、MegaFlow | 点监督、目标局部证据、完整预算下的实测差异 |
| 省掉稠密 cost volume | WAFT、现代相关采样实现 | 同预算真实球定位与可用对应；不能只比较理论显存 |
| 稀疏高分辨率查询 | QueryDet、SCV、DQAligner、MaST | 困难帧的覆盖损失与计算分配之间的新规律或机制 |
| 无匹配状态/拒绝错误对应 | SuperGlue 等匹配工作 | 现成球标签能否支持相应状态，以及拒配是否改善定位 |
| motion 子空间 | MoAlign、Midway | 是否超过普通投影、辅助定位与前景监督 |
| 目标运动与背景分解 | DMR 等 | 估计量、参考系和标签可识别性；不是换任务后再称首次 |
| motion reliability gate | MotionSqueeze、CMRTrack 等 | 可靠性究竟指对应正确还是使用后有益；两者如何验证 |

来源：[MotionSqueeze](https://arxiv.org/html/2007.09933)、[SELFY](https://arxiv.org/abs/2102.07092)、[GMFlow](https://arxiv.org/abs/2111.13680)、[FlowFormer](https://arxiv.org/abs/2203.16194)、[SuperGlue](https://psarlin.com/superglue/)、[QueryDet](https://openaccess.thecvf.com/content/CVPR2022/html/Yang_QueryDet_Cascaded_Sparse_Query_for_Accelerating_High-Resolution_Small_Object_Detection_CVPR_2022_paper.html)。近期条目的状态与适用边界见后文和文献附件。

### 6.3 两个容易做弱的基线

MotionSqueeze 不能被简化成一个容易失败的全局 soft-argmax 然后再拿多峰战胜它。原方法已有 kernel-soft-argmax 与相关置信线索。其原始任务是动作识别，迁移到球定位时，应保留合理的算子核心并标识为适配，而不是宣称复现了其所有原始结果。[MotionSqueeze §3.1、消融](https://arxiv.org/html/2007.09933)

RAFT 不能被描述为“只能看一个固定小窗口”。它的全对相关表示、相关金字塔和迭代采样，需要与这里的固定局部相关区分。另一方面，拥有全局相关条目也不保证极小球信息未在编码时弱化。[RAFT](https://arxiv.org/abs/2003.12039)

## 8. DINOv3 路线的研究判断

### 8.1 ConvNeXt-Tiny 是合适的首个候选，但只是候选

DINOv3 官方提供 ConvNeXt-Tiny/Small 和 ViT-S/16。ConvNeXt 的名义阶段步长为 4、8、16、32；ViT-S/16 的原生空间 token 网格为 stride 16，不会因选浅层 block 就自动变成 stride 4。相关架构事实有官方模型卡与源码支持。[DINOv3 官方模型卡](https://github.com/facebookresearch/dinov3/blob/main/MODEL_CARD.md)

ConvNeXt-Tiny 的价值在于它自然提供分层特征，便于以较少适配研究空间读出。Small 增加深度，不会自动增加最浅层空间分辨率；因此它不是“球看不清”的默认修复。

第一阶段优先 Tiny，一个 ViT-S/16 对照即可。把预算用于分辨率、层位和训练目标的区分，通常比同时搜索很多骨干更能回答研究问题。

### 8.2 必须拆开的三种“高分辨率”

1. 原始输入含有更多真实像素观测。
2. 骨干在更密网格上计算特征。
3. 低分辨率特征经插值或学习式 upsampler 生成更密输出。

第三项可以改善读出与边界，也可能利用原 RGB 引导，但它不能仅凭输出尺寸大就证明新增了独立观测。比较时应写明高分辨率来自哪里。

ViT 的多个 block 处于相同 patch lattice；ConvNeXt 不同 stage 同时改变深度与空间网格。两者“浅中深探针”的含义不同，不能画在同一张图里就假装控制了同样的变量。

### 8.3 先做少量有解释力的探针

冻结权重，比较三个层位、两个输入分辨率、同类小定位头。报告头的参数、输入网格和训练设置；通道不同造成投影参数差异时如实列出，不必为了精确相同参数引入复杂结构。

再做一个有限容量的非线性读出对照，以防线性探针低估信息可用性。若冻结探针弱、适度微调后强，应将结论写成“迁移适配不足”，而不是“预训练不可用”。

特别建议比较 patch/stem 前后的局部读出，以及受控平移下误差随采样相位的变化。若球落在不同 patch 边界时性能周期性变化，这比泛泛宣称深层语义不适合小目标更具体。受控变换的插值方式要固定，并与自然视频结果分开。

### 8.4 对 backbone 设计前提的尊重与科学归因可以同时成立

主系统仍采用现代预训练骨干。旧骨干是归因与强基线对照，不是要求退回旧系统。

但“旧 CNN vs DINOv3 ConvNeXt”改变了架构、预训练数据、训练目标和规模，不能把差值都叫作 DINO 预训练收益。若要进一步声称特定预训练目标有效，需要同架构、不同预训练权重的有限对照；这项实验在主张需要时开展，不必首轮全面排列组合。

### 8.5 上采样与适配的近邻也必须补齐

[FeatUp（ICLR 2024）](https://proceedings.iclr.cc/paper_files/paper/2024/file/c5601d99ed028448f29d1dae2e4a926d-Paper-Conference.pdf)、[LoftUp（ICCV 2025）](https://openaccess.thecvf.com/content/ICCV2025/html/Huang_LoftUp_Learning_a_Coordinate-Based_Feature_Upsampler_for_Vision_Foundation_Models_ICCV_2025_paper.html)、[AnyUp（2510.12764）](https://arxiv.org/html/2510.12764v1)、[RaysUp（2606.22749）](https://arxiv.org/html/2606.22749v1) 已覆盖多种基础视觉特征上采样思路。其中 AnyUp/RaysUp 的资料包含 DINOv3 通用稠密任务探针，但没有由这些结果直接建立高速小球 correspondence 的有效性。

因此，“DINOv3 + 高分辨率 adapter”也不能单列为新贡献。实际适配只选一个简单方案或一个成熟上采样器作空间对照，不应把四篇全部并入模型。

还有一个必须保留的归因：只用骨干浅层、只用额外细节分支、二者合用。如果 motion 增益几乎全来自普通浅层分支，论文应如实写成现代骨干系统中的细粒度时序机制，不声称从 DINO 深层特征中恢复了运动。

### 9.3 OTHR 的关键反证应保留，但不要过度外推

原稿摘录的 FlowFormer 四行对象区域误差已与 IJCAI 正式 Table 2 核对：clean 条件依次为 0.77245、0.13592、0.12936、0.12742；noise 条件依次为 0.77245、0.14927、0.15105、0.14959，对应原配置、加权 loss、OTHR、二者结合。它说明监督分配本身可以产生很大影响，而且组合不保证每项指标单调改善。[OTHR Table 2，PDF 第 6 页](https://www.ijcai.org/proceedings/2025/0136.pdf)

这是本项目做算子×监督归因的理由，不是证明某个具体加权方案必然解决网球。论文还说明其 tiny-object 数据中存在低速度情形，因此 FlyingTO 的结论也不能整体等价于体育中的高相对位移。

### 9.4 光流、点跟踪、模糊恢复各用来回答不同问题

[CoTracker3](https://arxiv.org/abs/2410.11831) 与 [TAPNext](https://arxiv.org/abs/2504.05579) 属于查询点跟踪近邻。若用 GT 球点初始化，测到的是有提示跟踪能力；完整球定位结果必须计入自动查询与重捕获。固定稀疏规则网格不保证采到几像素球。

[DeFMO](https://openaccess.thecvf.com/content/CVPR2021/html/Rozumnyi_DeFMO_Deblurring_and_Shape_Recovery_of_Fast_Moving_Objects_CVPR_2021_paper.html) 和 [FMO/TbD 研究谱系](https://cmp.felk.cvut.cz/fmo/) 已研究高速模糊物体的恢复。它们用于约束 blur 创新性；第一版无需扩展成子帧逆渲染。

[SEA-RAFT](https://arxiv.org/abs/2405.14793)、WAFT 和 [MegaFlow](https://arxiv.org/abs/2603.25739) 提供现代 flow 对照选择。无需把三者全部重训，至少选一个能挑战最终主张的强方案，并说明训练数据、推理成本及球区域可用性。

## 10. 数据约束决定什么能被证明

### 10.1 网球：协议名与计数都要有出处

WASB 数据表明确给出网球训练 7 games、65 clips、14,160 帧，测试 3 games、30 clips、5,675 帧，合计 19,835。原 TrackNet 文中还出现 20,844 的原始标注统计。**这不能直接判定其中一个错误：它们属于不同论文/使用口径。**应将 WASB 协议计数与本地实际下载清单分别记录。[WASB 数据表，PDF 第 7 页](https://papers.bmvc2023.org/0310.pdf)

TrackNetV4 仓库明确说明原数据缺少统一标准划分，并提供 game-level 与 clip-level 协议。引用时应称“TrackNetV4 作者提供的划分”，不能模糊写成唯一的 TrackNet 官方划分。[TrackNetV4 DATASET.md](https://raw.githubusercontent.com/TrackNetV4/TrackNetV4/main/docs/DATASET.md)

主泛化证据优先按比赛/来源隔离；clip-level 可保留为历史可比结果。验证来源从训练端另划，不把测试比赛当作反复改机制的开发集。训练窗口永远留在同一个 clip 内。

### 10.2 羽毛球：先固定实际发行版

作者说明按 match/rally 组织数据，给出 Frame、Visibility、X、Y，并说明不可见状态的占位坐标。页面与后续论文使用的职业/业余来源、测试扩展和总帧数存在不同口径，因此第一版记录实际版本与 match-level 清单，不争论一个脱离版本的唯一总数。[Shuttlecock 官方说明](https://hackmd.io/Nf8Rh1NrSrqNUzmO0sQKZw)

羽毛球很适合验证机制是否依赖网球颜色、形状与轨迹先验。但“分别训练后都有效”支持跨任务适用性，不等于“网球训练后零样本泛化”。这两类实验应独立命名。

### 10.3 BlurBall：主定位之外，先用标签做分析

已有拖影方向与半长度足以支持模糊条件分析，无需新增人工标注。第一版先比较相同定位监督下的 motion 效果，再决定是否增加 blur 辅助损失。

尤其应区分：拖影轴向；有符号速度方向；拖影半长度；帧间中心位移。轴向角通常涉及 \(\theta\) 与 \(\theta+\pi\) 的等价性，具体训练要服从发布文件的方向约定。

### 10.4 OpenTTGames：稀疏标签还带来采样偏差

OSAI 官方说明其视频为 120 FPS，球与分割标注围绕事件前 4 帧、后 12 帧组织；明确的 \((-1,-1)\) 表示无球，而缺少 frame key 是未知。可以读取标签帧周围的连续原视频作为输入，只在标签已知时计算相应损失。[OpenTTGames 官方页面](https://lab.osai.ai/)

除了索引正确性，还要注意**事件邻域偏差**：被评估的帧不一定代表整场比赛。模型在这些标签上取得好成绩，不能直接声明全视频普通运动、持球、长遮挡与无球时段同样可靠。

事件窗口重叠时，同一原帧不能重复计分；训练窗口数量、唯一监督帧数、有效中心对数是不同统计。稀疏标签也意味着某些上下文间隔没有双端真值，这些样本能训练定位，却不能自动训练对应。

### 10.5 完全遮挡标注不是直接像素证据

TOTNet 正式版明确说明完全遮挡时坐标根据前后位置作轨迹一致插值。因此原稿关于 TTA 这部分标签性质的提醒是正确的。它们可用于该公开协议的遮挡推断评价，不能被称为当前视觉对应真值。[TOTNet §数据标注，PDF 第 4 页](https://rbouadjenek.github.io/assets/pdf/YCVIU_104657.pdf)

同样，TrackNet 的难见/遮挡标注以及拖影取点规则需要保留来源语义。不能把 visibility 编码直接跨数据集统一为一个“球是否物理存在”的二分类。

### 10.6 不新增人工标注仍允许完成这些必要工作

读取标签说明、抽查坐标回画、检查视频时间与标签对齐、去重、保存划分、同步几何变换以及用已有标签计算位移，都不等于重新人工标数据。发现错误时，应使用公开可复现且对所有方法一致的处理规则。

允许自动遮挡或合成几何变换作诊断，但不得把产生的合成结果称作新的真实视频真值。没有标签支持的球直径、隐藏物理位置、相机真运动和全视频无球状态，均不要求补标。

OpenTTGames 官方公布 CC BY-NC-SA 4.0；本项目限定非商业研究，可以按其许可条件使用。其他数据按各自发布许可记录；公开下载与允许再分发并不相同。当前研究无须因此添加商业部署流程。[官方许可入口](https://creativecommons.org/licenses/by-nc-sa/4.0/)

## 11. “无可靠匹配”要拆成可评价的命题

### 11.1 至少四种事件

| 事件 | 能否从已有信息识别 | 正确用途 |
|---|---|---|
| 数据明确表示端点不可见/不可定位 | 取决于数据标签语义 | 按原协议训练状态或屏蔽视觉对应 |
| 真对应存在于评价标签，但搜索集合漏失 | 有双端标签时可诊断 | 算法覆盖失败，不能解释成物理无对应 |
| 预测对应落到错误位置 | 有可信双端位置和容差时可评价 | 匹配正确性及校准 |
| 加入 motion 后定位比外观路径更差 | 两种预测与目标标签均可获得 | 衡量 motion 的实际使用风险 |

缺标属于 unknown，不参与这些真值判断。两帧都可见也不保证图像中存在唯一可辨别对应，尤其当球无纹理、模糊强、多个反光点相似时。

### 11.2 匹配正确与使用有益不是同一个可靠性

设空间基线和时序模型的逐帧任务损失分别为 \(e_t^{app}\)、\(e_t^{temp}\)。这里使用预先固定的有界损失：对于有可信坐标的可定位帧，正确输出时使用截断、归一化的坐标误差，漏检或拒绝输出时取最大损失；其他已知状态单独统计状态错误，缺标不评分。可以分析：

\[
g_t=e_t^{app}-e_t^{temp}.
\]

对应正确但当前空间定位已经很准时，\(g_t\) 可能接近零；对应略偏却提供了正确大致区域时，也可能改善定位。因而一个 gate 若声称判断“何时信任 motion”，需要说明预测的是匹配正确率、集合覆盖率，还是使用后的风险。

上述 \(g_t\) 是分析量，不要求第一版新增一个预测头。先把外观和时序两条输出存下来，统计改善与损害即可。否则很容易因为再加一层 gate 就制造一个无法解释的“可靠性创新”。

### 11.3 一个 null 状态可以实现，但不能承载所有物理解释

标准匹配中允许 unmatched 是合理且已有先例的设计。第一版默认先分析拒配，不另加训练头。如后续确需监督 reject，“可接受候选”须操作化为：两端都有可信可定位标签，且候选落入预先固定的原图空间容差。真实目标未被搜索集合覆盖，另记为集合漏失；端点不可定位或缺标时，不用它监督物理 no-match。是否存在视觉证据、是否出画、是否应该拒绝当前位置是另外的问题。

评价 reject 时不能只报告保留下来的低误差：同时报告拒绝比例、完整定位召回、被拒绝帧的空间兜底表现，以及错误 motion 造成的新误检。拒绝所有关系会使匹配看似安全，却未必提高任务能力。

## 12. 相机运动与 blur：保留为受控轴，不立刻扩展系统

### 12.1 相机运动首先改变的是参考系

若背景参考映射 \(W_{j\to t}\) 将历史背景坐标映射到当前帧，则球相对该参考的观测残差可写作：

\[
r_{j\to t}=p_t-W_{j\to t}(p_j).
\]

它是图像平面中相对于估计背景模型的残差，不是完整的真实物体运动。空中球与场地不同平面、平移视差和拟合误差都可能进入残差。

相机跟球时，球在图像中可能近乎静止，背景移动；此时并不是所有 residual 定义都失效，而是不能把“图像中运动明显”当成有球的必要条件。应保留直接当前外观证据。

第一版优先比较无补偿和一个轻量背景条件；只有真实移动相机子集出现稳定失效，才增加显式仿射/单应性参考。背景拟合不可靠时允许退回无补偿，而不强迫每帧产生一个解释正确的相机运动。

### 12.2 合成相机扰动的证明边界

对连续帧施加已知时变二维变换 \(g_t\)，并同步改变现有坐标，可以测试坐标等变性和搜索对平移/缩放的敏感性。这不需要人工新标注。

但它没有完整模拟三维视差、真实曝光模糊和滚动快门。实验应称受控二维变换鲁棒性；真实相机泛化需要真实片段上的结果。

### 12.3 Blur 既可能帮助，也可能伤害

拖影会扩展可观察支持，也会降低局部对比并使方向上的位置不确定性增加。因此“模糊越长越难”是合理趋势假设，不是所有数据上必然单调成立的定律。

两帧拖影长度与方向不同，使用很小的中心点描述子可能匹配失败；更大的局部区域可能覆盖拖影，却混入更多背景。这里有一个有价值的候选问题：**对应支持应依据什么局部证据定义，才不把曝光轨迹误认为单个纹理点？**

这条路线要面对 BlurBall、FMO/DeFMO 和标准局部匹配。第一版先测中心点描述子与固定局部描述子的差异；若没有稳定的 blur 特定失败，不增加方向自适应采样或额外 blur head。

## 13. 建议收敛的科学问题与候选路线

### 13.1 主问题建议

> 在现代预训练视觉骨干与固定推理预算下，当当前帧球位置存在不确定性时，什么样的跨帧视觉关系能在不依赖真实查询点、不提前丢弃弱球候选的条件下，降低逐帧定位风险？

这个问题保留了 motion representation 主线，同时把“发现—匹配—使用”串起来。它不预设必须输出一个物理 flow field，也不预设必须构建两个 top-k 集合。

### 13.2 三条路线及其最强反对意见

| 路线 | 可检验机制 | 最强反对意见 | 当前优先级 |
|---|---|---|---|
| A：减少候选化前的证据损失 | 在细网格上保留当前弱证据，以有限历史锚点或受控查询搜索远处关系 | SCV、STSN、QueryDet 或简单单侧检索可能已足够 | 优先诊断；新算子尚未确定 |
| B：减少关系表示中的监督偏置 | 相同容量下，使已有中心监督保护任务相关关系 | 普通前景加权、辅助定位、监督对比学习解释全部收益 | 备选；由 OTHR 式归因先检验 |
| C：研究曝光支持与帧间对应的错配 | 更合适的局部支持在长拖影条件保持可用匹配 | 只是 BlurBall 标签/额外监督收益，或普通局部 patch 已解决 | 仅在 BlurBall 出现独立失败后推进 |

相机解耦、长时记忆、大教师、多峰关系和可靠性 gate 都暂时是可选机制或对照，不自动形成第四、第五个论文贡献。

### 13.3 一个更清楚但尚未构成创新的数学抽象

定义任务相关证据集合：

\[
\mathcal E_t(u)=\{(v,j,c_{t,j}(u,v),v-u,\Delta\tau_{t,j})\}_{(v,j)\in\mathcal S_t(u)}.
\]

其中 \(\mathcal S_t(u)\) 是实际执行的搜索集合，而不是名义上允许的所有位置。研究对象可以是如何选择 \(\mathcal S\)、如何编码 \(\mathcal E\)，以及这些关系是否对当前位置预测有增量价值。

预算可写为：

\[
\min_{\theta,\mathcal S}\;\mathbb E[\ell(\hat p_t,p_t)]
\quad\text{s.t.}\quad T_{e2e}\le B_T,\ M_{peak}\le B_M.
\]

这些公式只是问题定义，不是贡献。预算 \(B_T,B_M\) 需要实际硬件 profile 后确定；当前没有理由编造固定 FPS、显存或训练天数。

### 13.4 不建议现在为模型命名

没有证据前不取缩写、不画五个创新模块、不确定 loss 权重。先用描述性实验名区分：单帧、简单时序、固定局部匹配、单侧稀疏检索、两端候选匹配。模型结构应由诊断中的主要失败决定。

如果最后只有一个很小的修改有效，它仍然可能有论文价值，但必须带来清楚、可重复、超出已有方法直接适配的认识。反过来，模块多、名称新和总参数大都不能弥补缺乏机制证据。

## 14. 第一批实验：按决策价值排序

以下是后续执行队列，不表示本轮已经运行。首轮先在一个明确的网球协议上做，BlurBall 用于检验模糊相关结论；羽毛球及 OpenTTGames 随证据需求逐步加入。

### E0：数据与评价器是否正确

输出：数据版本、来源与划分、唯一标注帧数、双端可监督帧对数、可见性分布、坐标定义。

最小检查：GT 作预测达到协议上限；固定像素偏移按预期降低定位率；缺标不记负例；跨 clip 的窗口数为零；原帧号及坐标正反变换一致。这里需要可运行的数据检查，当前文献审查不提前搭大工程。

### E1：空间证据是否足够

比较现代骨干的三个层位、两个分辨率和有限容量探针，先确认球定位能力。必要时比较浅层细节单独使用与骨干特征融合。

决策：若主要增益来自输入分辨率，先修复空间基线；若深层读出弱、浅层可靠，motion 匹配优先放在可读特征上；若微调解决问题，不能据冻结探针否定现代骨干。

### E2：时序是否具有增量价值

使用同一空间骨干和定位头，比较单帧、共享编码的简单三帧融合、差分、短时间卷积。再加入仅用各帧 heatmap/预测坐标的时序融合。

如果用 \((t-1,t,t+1)\)，要加邻帧预测坐标插值对照；若用过去帧，则加短时外推对照。两个对照的运动先验不要故意设得过强，以免在反弹处系统性失败后被轻易击败。

决策：若简单时序已经解释改善，继续分析残余错误；若没有任何有用增量，暂不立显式 correspondence 机制。

### E3：探针测到的是描述子还是独立检测

| 诊断 | Query 来源 | 被检索端 | 能证明的范围 |
|---|---|---|---|
| 描述子正负间隔 | 两端 GT 用于采样 | 固定正负对 | 条件可分性，不是检索或检测 |
| 历史 oracle 检索 | 历史 GT 球点 | 当前全图 | 已知历史球时能否找到当前球 |
| 历史预测检索 | 自动历史候选 | 当前全图 | 自动锚点条件下的检索能力 |
| 完整候选系统 | 所有输入均自动 | 当前候选或全图，明确区别 | 最终定位与失锁 |

GT 当前 query 检索历史仍是合法的反向描述子诊断，前提是清楚标为 oracle；它不是训练/测试泄漏本身，也不能证明当前自动定位。

每个检索探针加 query-blind 被检索端检测对照：当前查历史时只按历史球分数排序，历史查当前时只按当前球分数排序。对历史点加与模型实际误差尺度相当的扰动，不机械使用 ±若干特征格而忽略其在原图中可能非常大。

### E4：搜索覆盖与关系排序分离

固定编码器，比较：细特征固定局部窗口；低分辨率全局匹配加细化；两端候选；单侧候选×稠密细网格。预算按实际相关条目和完整运行成本报告。

分别输出当前覆盖、历史覆盖、联合覆盖、给定覆盖的正确匹配率、完整定位率。既报告全集，也报告固定空间基线失败集合 \(\mathcal H\)。覆盖与排序不需要每项同时上升，关键是其组合及最终任务在同预算下改善。

### E5：关系输入的因子化对照

比较相同候选上的 score-only、score+geometry、correlation-only、full。去掉某类输入后允许模型按相同规则重新训练，而不是仅在测试中破坏它。

再用常数化/置换 correlation 作辅助敏感性测试。置换导致下降是“模型依赖该输入”的证据，**不是独立证明它学到了正确 motion**；仍需要匹配准确性、真实时序上下文和最终定位的共同支持。

### E6：监督效应与算子效应分离

在强简单时序和候选新机制上，分别使用共同定位目标，以及共同目标加对应/前景监督。若两者都从相同监督中获益，不能把增益全部记给新结构。

纯空间基线没有关系输出时，不强迫它计算没有意义的对应 CE；可提供同样标签信息的辅助头，并另列训练后移除辅助头的对照。公平指学习机会与信息清楚，不是所有网络机械套同一个 loss 名称。

### E7：同一目标帧改变上下文间隔

保持目标帧 \(I_t,p_t\) 不变，在可获取真实连续视频时改变历史/未来采样间隔。限制在同一 clip，记录实际时间，不把稀疏标签重编号。

它固定当前图像难度，测量时间间隔变化的联合影响；邻帧外观、模糊、遮挡和运动阶段仍随之变化，不能单独归因于位移。结合 E4 固定特征与帧对、只改变搜索范围的实验，才能判断搜索瓶颈。双端对应评估只在需要的端点有可信标签时进行；不同间隔的比较尽量使用共同有效帧集合，避免因标签覆盖不同改变测试难度。

### E8：BlurBall 与跨球种复查

先固定机制在网球上选定的主要配置，在 BlurBall 上按预先约定的训练/验证规则运行，报告模糊半长度与位移的交叉分桶。样本不足时减少桶数，不画稀疏而不稳定的复杂图。

再在羽毛球上验证同机制。如果每个数据集都需要完全不同结构才能生效，就不能轻易宣称通用 motion 表示；若只需普通训练适配，应清楚区分结构通用与零样本泛化。

## 15. 公平归因：两个 2×2 之外还要补什么

### 15.1 推荐使用 2×3 主表

| | 单帧/无时序 | 强简单时序 | 新 motion 机制 |
|---|---|---|---|
| 旧骨干 | A | B | C |
| 现代骨干 | D | E | F |

\(D-A\) 是整个骨干/预训练替换的效果；\(E-D\) 是简单时序增量；\(F-E\) 才是新机制相对合理时序起点的增量。

\((F-E)-(C-B)\) 可以描述机制与骨干的交互：新机制是否特别受益于现代特征。但它不是严格的普遍因果效应估计；架构容量、优化适配和训练方差仍需解释。

预算有限时，先在现代骨干上跑 D/E/F，再补旧骨干的关键格。不要从一开始把所有骨干、帧数、分辨率、loss 做笛卡尔积。

### 15.2 必须共享的条件

输入像素、合法帧集合、未来信息、空间细节通路、定位目标定义、数据增强规则、标签来源、选模规则、评估容差和后处理，应在机制比较中保持一致。

架构不同可能需要不同合理学习率，不能把所有基线锁死在一个只适合新方法的超参上。应给主要方法同样有限的调参预算，记录验证选择；“完全相同训练超参”不是公平性的充分保证。

### 15.3 准确率公平与资源公平分表

同骨干同分辨率比较有助归因，但新 motion 可能更贵；同延迟预算比较体现实际权衡，却可能改变分辨率或通道。两张表各自回答问题，不要求在一个实验中同时锁死所有不可兼得的量。

外部论文成绩单列为作者报告。不同 split、容差、可见性、未来帧和后处理的 F1 不直接混排。完整重训、忠实重实现、使用作者权重与仅有论文数字分别标注。

### 15.4 三帧双向不是错误，也不等于在线

逐帧定位是一种输出粒度，不要求必须因果。用户未要求实时部署，三帧中心预测可以成为第一版主设定；只要明确一帧前瞻，并给所有主对照同样的上下文。

若后续主张在线或实时，需要另训因果版本，报告等待未来帧的延迟。仅把输入索引从 \((t-1,t,t+1)\) 改成 \((t-2,t-1,t)\) 而不重新验证，不足以证明因果版本有效。

## 16. 高效性需要一个具体的计算反例

### 16.1 不同搜索组织的成本

令细特征网格有 \(N\) 个位置，通道 \(C\)，局部半径 \(r\)，稀疏候选数 \(R\)，每个 query 保留 \(K\) 个关系。

| 组织 | 相关计算数量级 | 主要风险 |
|---|---|---|
| 朴素全对 | \(N^2C\) | 高分辨率下激活与计算贵 |
| 固定局部 | \(N(2r+1)^2C\) | 真对应可能不在实际采样范围 |
| 两端候选 | \(R^2C\) | 两端发现都可能漏球 |
| 单侧候选×稠密另一端 | \(NRC\) | 一端覆盖仍需保证，计算未必小到可忽略 |
| 每点 top-K 稀疏关系存储 | 存储 \(NK\)，搜索计算另计 | 获得 top-K 可能仍需昂贵全局比较 |

**存储稀疏、计算稀疏和候选稀疏是三件事。**Exact top-k 若先计算所有相似度，只减少保存或后续处理，并没有自动去掉全对计算。分块可以降峰值显存，但未必降低总运算。

### 16.2 一个可复算的说明性预算

下表仅计算单帧对、单层、单标量相关项；FP16 只计相关数组本身，不含特征、梯度、索引、其他层和模型。数值为算术例子，不是测得 GPU 显存或模型速度。

| 输入与步长 | \(N\) | 全对条目 | FP16 相关数组 | 局部 \(r=4\) 条目 | 单侧 \(R=64\) 条目 |
|---|---:|---:|---:|---:|---:|
| 512×288，stride 4 | 9,216 | 84,934,656 | 162 MiB | 746,496 | 589,824 |
| 512×288，stride 2 | 36,864 | 1,358,954,496 | 2,592 MiB | 2,985,984 | 2,359,296 |
| 768×432，stride 4 | 20,736 | 429,981,696 | 820.125 MiB | 1,679,616 | 1,327,104 |

这个例子说明：在某些预算下，单侧 64 个锚点的全范围关系数量可以低于逐点 9×9 局部相关。它不是速度保证，但足以说明**无需为了远范围搜索立即接受两端候选的召回损失**。

此外，512×288 的 stride-16 网格只有 576 个位置，全对仅 331,776 项。因此“粗全局＋细局部”也应当有机会获胜。只有实验证明粗网格无法给球提供足够覆盖，才能以该失效支持新的细粒度搜索。

### 16.3 Amdahl 式检查

假设 matching 占完整时间比例 \(f\)，仅该部分加速 \(k\) 倍，其余不变，理想整体加速为：

\[
S=\frac{1}{(1-f)+f/k}.
\]

如果 \(f=0.05,k=10\)，理想整体只约 1.047 倍。不能据此写出大幅端到端加速。反之，即使延迟改善小，显存下降允许更高输入分辨率并改善定位，也可以是有价值的预算权衡；不应机械设置“matching 小于 5% 就必须放弃”的门槛。

### 16.4 实测应包含什么

同硬件、同精度下报告 batch=1 延迟、稳态吞吐、峰值显存、分辨率、输入/输出帧数、是否前瞻，以及解码与预处理是否计入。候选生成、top-k、gather/scatter、特征重算都在账内。

滑动三帧窗口可缓存逐帧独立编码的骨干特征；但若深层特征已混入当前窗口的时序信息，则不能无条件跨窗口复用。缓存策略要对适用的基线同样开放。吞吐按唯一输出原帧计算，不按重复窗口或重复预测计数。

第一版先证明机制，不需要开发 CUDA 内核。若 profile 显示执行实现才是瓶颈，再决定是否采用现有高效算子；不要让内核工程反过来替代 motion 研究。

## 17. 评价：不要让指标掩盖 motion 的失败

### 17.1 定位指标分三个层次

第一层，严格保留各公开数据协议的 TP/FP/FN、visibility 与像素容差定义，用于与任务文献比较。定位偏离球的位置在某些协议中如何记为 FP/FN，要遵照原规则。

第二层，在共同坐标系下报告多个预先固定容差的 PCK/定位召回曲线，以及已知状态帧的 precision、recall、F1。未检出不能从 PCK 分母消失；只有 true-positive 上的坐标误差会偏爱保守模型。

第三层，给出分阶段机制诊断：支持覆盖、条件匹配、候选外可达性、融合后定位、拒配与误报。机制表不代替最终定位表，最终 F1 也不代替机制表。

### 17.2 用“救回与损害”揭示实际收益

在固定空间基线与同一测试样本上，将时序结果分为：

| 空间基线 | 时序模型 | 解释 |
|---|---|---|
| 正确 | 正确 | 保持能力；还可比较精细误差 |
| 错误 | 正确 | 救回，需进一步定位是搜索、匹配还是轨迹推断起作用 |
| 正确 | 错误 | 时间信息造成损害，必须展示而不能只挑成功案例 |
| 错误 | 错误 | 残余困难；检查观测、候选、关系和读出 |

为避免某个容差决定全部叙事，可同时展示预定容差下的转移表与连续误差差值分布。不要在观察测试结果后只选择最漂亮的阈值。

### 17.3 位移与模糊需要配对和交叉分析

高位移帧往往同时有更长拖影、更多出画和击球突变，仅按位移分桶看到性能下降，不能证明是局部搜索范围导致。

优先采用 E7 的同目标帧上下文间隔实验；在 BlurBall 另作位移×模糊的少量交叉桶。报告每桶有效帧数与独立 clip 数。稀疏标签造成不同桶来自不同来源时，应明示，不能把几百个相邻帧当作几百次独立验证。

没有现成事件标签时，轨迹转角只能称几何代理，不能命名为真实 hit/bounce 分桶。低位移处角度对坐标噪声尤其敏感，应设置有效性条件。

### 17.4 校准首先需要一个清楚的事件

若校准的是“在容差内匹配正确”，就在可信双端标签上评价这一事件；若校准的是“候选集合覆盖真对应”，用覆盖指标，二者不能混用。

可以用可靠性图、Brier score 或风险—覆盖曲线。位置热图的最大值受温度、网格大小和目标分布影响，不能直接作为可跨数据集比较的概率。

只在真对应已覆盖的条件下做校准有诊断价值，但会隐去搜索失败。论文应同时给出条件校准与完整系统的检出/拒绝结果；若只有正位置、没有完整负例标签，就不能计算全视频无球误报率。

### 17.5 统计单位应尽量是比赛或来源

训练随机种子衡量优化波动，比赛/视频来源衡量数据泛化波动，两者不同。建议最终关键配置使用多个种子，并展示逐比赛的配对差值。

若使用 cluster bootstrap，应以来源/比赛为外层重采样单位，保留其内部帧相关性。最终独立测试来源很少时，不能靠大量 bootstrap 次数制造强泛化证据；直接展示各来源结果及范围更诚实。

困难桶阈值在训练/验证阶段确定，测试固定。若反复依据测试失败改设计，就把该集合视作开发集，并保留另一个独立来源用于最终检验。无需声称公开比赛从未进入大型预训练数据：在无法审计预训练全集时，只能说明未知；同骨干增量比较有助控制这一因素，但不能证明绝对无污染。

## 18. 多轮对抗性审查的汇总裁决

这里记录八个审查视角及修订后的裁决，不把讨论次数当成实验证据，也不宣称已经模拟了真实会议审稿。

| 轮次 | 最强质疑 | 结论 | 必须留下的证据 |
|---|---|---|---|
| 1：问题定义 | 几像素、高速、大位移是不是新问题 | 不是；保留任务，撤掉一般性“首次发现” | Devon/SCV/OTHR 等近邻差异 |
| 2：机制可识别性 | 对应是否退化为两帧独立检测 | 是实质风险；现有 2×2 不足以排除 | query-blind、score+geometry、关系因子化 |
| 3：搜索覆盖 | 新方法是否只在先找到球后才有效 | 两端候选尤其危险；优先测困难集合 | 当前/历史/联合覆盖，完整救回与损害 |
| 4：空间归因 | 真正有用的是 DINO 还是浅层支路 | 需要实测；主骨干现代化与运动证据来源是两件事 | 层/分辨率探针、shallow-only 与 combined |
| 5：监督与标签 | 轨迹插值、blur 标签、额外 loss 是否造成收益 | 原稿原则正确，需在实验中具体落实 | provenance、算子×监督、固定坐标语义 |
| 6：可靠性 | null 是否把算法漏检重新解释成合理拒绝 | 不能合并所有语义；先做诊断而非新增 gate | 已知状态、覆盖失败、匹配正确性、定位使用风险 |
| 7：效率 | 稀疏头是否只优化了系统中很小部分 | 理论阶数不足；也要允许显存换分辨率的真实价值 | 完整 profile、粗到细强对照、Pareto |
| 8：论文成立性 | 即使提高 F1，是否只是一套更好的工程配方 | 当前未解决；需要一个清楚机制和可复现作用范围 | 同预算强基线、跨来源、失败边界、独立验证 |

### 对审查意见本身也要反驳

严格审查不意味着所有指控都接受。以下几种过强结论应当否决：

**“GT query 都是泄漏。”**不对。清楚标记且仅用于 oracle 诊断是合法的，问题是把条件诊断冒充自动定位。

**“两端召回率必须直接相乘。”**不对。乘积需要独立性假设，实际应测联合覆盖；上限也只约束受候选支持限制的路径。

**“逐帧定位必须因果。”**不对。因果/双向是输入协议，逐帧是输出粒度。

**“只要 correlation 被置换后性能下降就证明 motion 正确。”**不对。这只证明对输入的依赖，仍可能是错误统计或分布外敏感性。

**“如果不能救回候选外的球，方法就没有价值。”**不对。候选重排也可能显著消除歧义并形成有效贡献；只是不能据此声称解决了发现阶段的漏球问题。

**“如果浅层支路最有用，项目就违背现代骨干前提。”**不对。主系统仍可使用现代骨干，论文只需如实交代各部分作用。

**“最新论文越多，研究就越稳。”**不对。查重需要广，核心论证需要深。最接近的一篇论文可能比几十篇视频问答方法更有决定性。

## 19. 怎样判断它接近一篇有竞争力的论文

### 19.1 不以固定提升百分点定义论文等级

没有“提高 1% 就能投 B、提高 3% 就能投 A”的通用规则。小数据集上高 F1 区间的一点变化可能重要，也可能只来自少数帧、阈值和种子。研究价值需要结合机制、可靠性、困难条件、来源泛化和成本判断。

现阶段的目标不是保证某个会议，而是形成如下论证：

> 我们定位了一个被强基线仍然暴露的具体失效；已有方案的直接适配无法在相同预算解决它；一个明确机制改变了该失效，且对应与最终定位结果一致支持；收益可以在独立体育来源上复现，并说明不可用的边界。

### 19.2 三种可能结果与诚实的论文方向

| 后续结果 | 可支持的论文方向 | 不应声称 |
|---|---|---|
| 主要收益来自空间读出与采样相位修复 | 预训练特征在微小定位中的可读性/适配研究 | 已解决复杂 motion 表示 |
| 强简单 motion 已足够，新监督贡献最大 | 任务监督如何保护稀疏运动证据 | 新匹配结构贡献了全部收益 |
| 新搜索/关系机制在高位移困难帧有稳定净收益 | 预算约束的任务相关 correspondence | 泛化到所有小目标、所有相机、所有遮挡 |

如果只有完整系统总体 F1 改善，而机制拆分不能解释，暂时应把它视为有用的工程结果，继续找原因。不要为了达到论文目标把证据重新叙述成不存在的创新。

### 19.3 关于 CCF B 及以上目标

可以保持这一目标，但会议选择应晚于核心证据。内容上可关注多媒体、视频分析与计算机视觉主会；机制有更广泛意义时再扩大投稿范围。

具体等级、单位采用的目录版本和论文类型按官方目录核验。本轮不提供未经完整核验的最新等级表，不把 CVPR Workshop 等同 CVPR 主会，也不编造未来截稿日期。[CCF 官方目录入口](https://www.ccf.org.cn/Academic_Evaluation/By_category/)

## 20. 长期项目的推进方式

### 20.1 以证据门槛推进，而非先排大模型开发

| 阶段 | 产物 | 进入下一阶段的条件 | 失败后的合理动作 |
|---|---|---|---|
| P0 文献与任务契约 | 本报告、近邻差异、可用标签说明 | 关键任务与创新冲突清楚 | 补最接近正文，不扩展模型 |
| P1 数据与空间诊断 | 固定 manifest、评价检查、现代空间基线 | 位置语义可靠，知道哪些层能读出球 | 修数据/空间适配 |
| P2 motion 增量诊断 | E2–E5 的小范围结果 | 排除明显独立检测/轨迹捷径后仍有有用关系 | 采用简单方法或收窄研究问题 |
| P3 一个新机制 | 最小实现、强替代对照、失败案例 | 新机制确实改变预期失效 | 删除无收益设计，不追加模块维护故事 |
| P4 归因与泛化 | 2×3、监督消融、多种子、跨来源结果 | 主张稳定、协议公平 | 降低主张或重新定位原因 |
| P5 效率与写作 | Pareto、完整配置、论文与复现说明 | 每个主要论断有对应证据 | 删除无法支撑的贡献与范围 |

P0 已完成本轮范围内的审查交付，不代表所有关键论文都已完整复现。P1 以后尚未执行，本轮没有创建训练代码、下载大规模数据或启动训练。

### 20.2 优先保存四类研究记录

**假设记录：**假设、支持证据、反例、当前状态。特别记录被否定的机制及原因，避免几周后换个名字再做一次。

**实验记录：**数据版本、代码版本、输入协议、训练设置、唯一改变项、选模规则、结果、失败、下一步决策。记录普通结果，不只保存最佳 checkpoint。

**文献记录：**原始链接、版本、发表状态、读到哪里、是否运行、与当前机制的差异。来源日期与搜索引擎抓取日期分开。

**协议记录：**可见性、缺标、原时间索引、比赛划分、模糊中心、容差、未来帧和计算账单。协议改变时给新名字，不让同名实验悄悄更换任务。

这些可以从少量 Markdown 与 CSV 开始。没有必要先建庞大的实验平台、插件系统或通用 dataset framework。

### 20.3 资源未知时仍可以做出的决定

当前不需要硬件或 deadline 才能决定：不跨 clip；不新增人工标签；主骨干现代化；先强空间基线；先诊断再方法；原协议与统一归因分表。

进入训练时才需要实际 GPU/显存、已下载数据版本和可投入时间。用短跑 profile 决定 batch、分辨率与并行实验数，不用未经测量的训练小时承诺影响研究判断。

### 21.3 实际检索覆盖与未完成边界

本轮执行了原稿题名/arXiv ID 的定向核对，以及如下关键词族的搜索；使用 arXiv、CVF、ICLR、IJCAI、AAAI、作者论文页与官方仓库，第三方摘要仅作发现入口，不作为关键技术主张的最终依据。

| 关键词族 | 主要目的 |
|---|---|
| sports ball tracking / ball detection / tiny ball + 2025/2026 | 补 TrackNet 系列与球类直接近邻 |
| small fast moving / tiny object motion / large displacement | 补红外、UAV、tiny flow 的创新冲突 |
| sparse correlation / global matching / efficient cost sampling | 检查范围、支持与计算的既有解法 |
| motion representation / latent / subspace / localized motion | 检查预训练与 motion 学习目标 |
| confidence / occlusion / unmatched / motion reliability | 检查拒配、可靠性与状态语义 |
| DINOv3 / feature upsampling / dense probing | 检查现代骨干与空间适配前史 |
| optical flow / correspondence + August/September 2026 | 扫描近两个月新稿并按实际任务筛选 |

**充分性判断：**主要问题轴已经有直接近邻，至少三类新增先例改变了方法优先级；可以进入低成本诊断阶段。**完备性判断：**没有进行全 arXiv 库/API 的可复现全量枚举，没有逐篇全文与代码复现，无法声称系统综述式穷尽，也不能保证不存在尚未被索引的新稿。

最接近最终算子的论文需要全文级复查；外围工作摘要级可用于限定宽泛主张，不能用于断言其具体模块没有某个能力。特别是 V2/V6/LaTBT 的完整实现、部分 IEEE 正文、最新预印本最终接收状态和数据全量发布，仍须按实际研究需要补证。

持续查重的合理节奏是：确定核心假设时一次；选定具体算子时一次；主要实验成形时一次；投稿前再做近期更新。没有必要每天因为一篇弱相关预印本重写整个研究问题。

## 22. 需要长期保留的结论

**第一，保留研究方向，暂不锁定模型。**现代骨干与 motion 表示主线符合目标；最有希望的突破点应从具体失败中产生。

**第二，先验证 motion 的独立使用价值。**优先排除独立检测配对、简单轨迹融合和额外监督，避免把一个好系统误解为一种新运动表示。

**第三，把弱证据在候选化前的命运作为首要诊断。**先看需要被救回的球是否还能进入关系路径，再决定远搜索、多峰或拒配是否值得投入。

**第四，原稿中的正确谨慎应保留，新增的谨慎也必须可执行。**下一步最有价值的产物不是更多文字或更大的网络图，而是一个可靠协议下的空间基线、时序增量表、困难帧覆盖表和完整成本表。

当前达到的是**值得开始有边界、可证伪的实验**，尚未达到“算法创新已成立”。如果这些实验否定当前偏好的路线，研究仍然可以继续；应由证据决定转向，而不是用额外模块维持既定叙事。
