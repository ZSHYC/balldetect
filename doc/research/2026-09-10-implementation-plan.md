# 从空间证据到运动架构的实施设计

日期：2026-09-10。性质：实施设计与计划；用户已授权自主实施与持续实验。完整目标仍是具有实证贡献的运动表征论文，本文件只确定第一个可检验阶段。

## 首轮选择及理由

三条可行路径是直接端到端训练多帧定位、冻结空间探针、先做 GT query 对应探针。先做冻结空间探针：它能以一次特征提取支持多层读出与后续诊断，快速暴露坐标、网格和读出问题。端到端训练是后续必要竞争解释；GT query 对应不能代替自动发现，放在有空间起点后。采用[空间协议](../protocols/tennis-spatial-probe-v1.md)。

首轮模型是 `RGB -> 冻结 DINOv3 ConvNeXt-Tiny -> 独立 stage 特征 -> 归一化线性空间/无球头`。四个头分别训练，不融合。若粗层量化上限明显不足，先调整读出而不是宣判特征丢失；若线性头不足但非线性头显著改善，归因于可读性/容量而非信息不可恢复。若所有层都差，先做少量样本拟合检查、输入尺度与微调对照，不直接上 motion。

空间起点成立后，固定相同监督与输入范围比较当前帧、廉价时间特征融合和短窗位置响应推理；再根据实际残余错误选择局部/远程对应搜索。研究总纲的 H1/H2/H3 是互相竞争的假设，不预先组装成一个网络。最终保留 old/new × no/simple/new motion 归因、另一球种和 blur 验证要求。

## 文件与执行顺序

使用 writing-plans 的先定接口再验证方式，在当前研究分支直接执行；用户已明确授权，不增加逐阶段审批或额外工作树。

1. `src/ballmotion/tennis.py`：一次读入 Tennis 索引，明确标签状态与按原帧号采样；坐标到网格与反向变换。`tests/test_spatial_probe.py` 先写半像素、无球/非法标签和错位 FP/FN 的手算样例；预期未实现时失败，实现后通过。
2. `src/ballmotion/probe.py`：读出头、分类目标、预测与分组评价。合成特征小数据可拟合，检查梯度和输出位置，不能以 smoke 成功代替真实性能。
3. `scripts/cache_tennis_features.py`：复用原作者代码直接严格加载本地权重；一次前向保存所有 stage，float32 算、float16 存。缓存配置和原帧身份绑定，不缓存重复窗口；GPU forward/保存误差检查通过后再提取开发集合。
4. `scripts/train_spatial_probe.py`：从 `.npy` mmap 读取单 stage，固定 seed 训练，保存日志、最佳验证模型与每帧预测；不打开最终测试集。先 smoke，再四层同设定读出。`third_party/README.md` 记录上游版本与获取命令，`requirements.txt` 只记录实际依赖。
5. `doc/experiments/2026-09-10-spatial-probe.md` 写实际成绩、网格上限、失败解释及下一实验。同步入口与 Git 提交；根据新证据继续尺度、读出或时序实验。

## 验证会改变哪些动作

坐标映射失败则修正几何代码，指标手算失败则修正评价器，不运行训练。严格权重加载或真实 forward 失败则修复模型接入。特征 float16 转换若溢出/误差明显则改存 float32。小样本不能拟合则检查目标与优化，不能烧时间做大规模比较。真实结果受网格限制则优先改读出；仅泛化失败则研究场景偏差、数据量与表示，而不是重复相同训练。

所有长期结论必须经正式训练与对照复核；不承诺任何具体论文录用等级或“完美”结果。
